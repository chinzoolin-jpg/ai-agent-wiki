AI Agent 到底是什麼

簡單講就是幫忙做任務的 AI。不只跟人聊天，還能決定下一步要做什麼，必要時去用工具。

它通常會先看目標，過程中找資料、處理結果，再判斷事情做完沒。不是每個程式都能隨便操作電腦，還是要看它被開放什麼工具。

C2 / 概念頁

跟一般聊天機器人差在哪

一般問答型聊天機器人大多是問一句，回一句。

Agent 的重點不是名字，而是它能不能照目標走好幾步，用工具、看工具回來的資料，必要時再做下一步。

有些聊天產品本來就可以使用工具，所以這裡是方便理解的比較，不是絕對的分類。

C3 / 概念頁

大概需要什麼零件

模型 LLM：看懂問題，幫忙想下一步。

指令 Instructions：告訴 AI 要做什麼、哪些事不能做。

工具 Tools：像查資料、讀檔、呼叫服務。沒有開放工具的功能，不能假裝已經做了。

有些系統會加上記憶或知識庫，但不是每一種 Agent 都一定有這些。

C4 / 概念頁

Agent 會一直重複的步驟

接到任務 → 決定下一步 → 如果需要就使用工具 → 看工具回傳什麼 → 再決定下一步。

如果沒有完成就繼續跑，完成了就結束。遇到不能處理或需要權限的事情，也要停下來問人。

這個反覆檢查結果的過程，就是我們常講的 loop。

C5 / 概念頁

生活例子：幫忙整理一日遊

假設你要安排一日遊。一般聊天 AI 可能先給你一份建議。

如果是有相關權限和工具的 Agent，它可以查地點、找營業時間、比較移動距離，再排成一份行程。

這只是示範可能的流程，不代表這份作業真的幫人訂位，真實資料還是要查證。

C6 / 概念頁

Agent 也會出錯

資料本身可能錯，工具也會失敗，結果不一定可靠。

像付款、寄信、刪除檔案等可能造成影響的操作，最好先得到人的同意。

如果一直卡在同一步，可以限制重試次數；來源不夠時回到找資料，不要硬編出答案。

C7 / 概念頁

Workflow 和 Graph

Workflow 是做事的順序。Graph 就是把各個步驟畫成節點，再用箭頭連起來。

例如資料夠不夠？夠就往下做；不夠就回去查。

本作業用的 graph 是：找資料 → 整理 Wiki → 查 Wiki → 做簡報 → 檢查；檢查沒過就回到前面修改。
